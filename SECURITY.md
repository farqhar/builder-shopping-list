# Security policy

## Reporting a vulnerability

Found a security problem in this repo, such as a skill that could leak a
secret, an example that does something unsafe, or a workflow that could be
abused? **Please report it privately, not in a public issue.**

1. Go to this repository's **Security** tab, then **Advisories**.
2. Click **Report a vulnerability** and describe what you found.

Only the maintainer can see the report. If that button isn't there, contact
the maintainer through their GitHub profile ([@farqhar](https://github.com/farqhar))
and say you have a security report, without the details.

Please don't include real secrets, keys or other people's data in a report.

## What's in scope

- The skills in [`skills/`](skills/), the code in [`examples/`](examples/) and
  the workflows in [`.github/workflows/`](.github/workflows/)

**Not a vulnerability, but please tell us:** advice in a checklist or guide
that's wrong or out of date. Use the
[Report a mistake](CONTRIBUTING.md#ways-to-help) issue form, because public
discussion helps everyone learn.

## What to expect

This is a volunteer-run learning resource, not a commercial product. Reports
are read and answered as quickly as possible, and fixes are credited to the
reporter unless they'd rather stay anonymous.

Learn more about why every project should have one of these in the
[governance checklist](checklists/08-governance.md#give-people-a-private-way-to-report-security-problems).
